Created nine tables:

- `public.planzo_profiles`, `planzo_trips`, `planzo_trip_windows`, `planzo_trip_members`, `planzo_brief_status`.
- `planzo_private.trip_invites`, `member_brief_drafts`, `member_brief_revisions`, `operation_receipts`.

All have RLS enabled. Public shared tables have trip/owner read policies and no direct client mutation grants. Private tables are non-exposed, have no client table grants and intentionally use RLS default deny. Their narrowly checked server functions return only the requesting person's raw brief. The security advisor has no warning/error findings; four INFO findings describe the deliberate absence of permissive RLS policies on those private tables. [Explanation of this advisor](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

Public endpoints `planzo_api` and `planzo_invite_preview` use SECURITY INVOKER. Privileged implementation is confined to the private schema. The existing `rls_auto_enable` event trigger is preserved; unnecessary anonymous/authenticated/public EXECUTE grants were revoked. Every authenticated write derives its actor from Auth and requires a verified, non-anonymous, non-banned identity. Membership and organiser role cannot be selected by the client.

The checked actions are profile name, own trip list, atomic/idempotent trip creation, safe workspace, invitation creation/list/revocation, idempotent verified-user joining, and own draft/confirmed brief save. Invitation tokens are random 256-bit values; only hashes are stored. They expire at the earlier of seven days and the trip response deadline. Revocation prevents future joins; it does not eject existing members. At most eight members and ten unexpired active invites are permitted. There is one to three travel windows and a minimum group size of four to eight. Live plans remain at collecting stage in this slice.
